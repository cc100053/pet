# 多寵物同伴系統 (Multi-Pet System) 設計文檔

## 1. 核心機制 (Core Mechanics)
- **房間容納量**：每間房最多可同時容納 5 隻寵物。
- **狀態共享**：飽食度 (Hunger) 同好感度 (Affection) 等狀態與「房間」綁定，而非單一寵物。所有寵物共享同一個房間的狀態數值。
- **經濟與消耗**：維持現有消耗品設定。房間內有複數寵物亦**不需要**增加消耗品的消耗量，無需對當前數值系統作額外調整。

## 2. 獲取與觸發機制 (Acquisition & Trigger)
- **「寵物券」道具**：玩家可於商店購買「寵物券」。
- **背包與防呆機制**：
  - 購買後，「寵物券」將存入玩家背包或以獨立道具形式存在。
  - 使用寵物券後，會立即彈出「選擇寵物」頁面（類似「回家信」邏輯）。
  - 若玩家中途退出或意外斷線，寵物券不會消耗，可於下次重新打開背包觸發，確保不會流失。

## 3. 日常互動 (Daily Interaction)
- **聊天系統**：保留現有聊天系統，不作任何改動。維持現有對答與觸發邏輯，不需因多寵物而增加額外判斷。
- **餵食機制**：當玩家丟出食物時，房間內**所有**寵物均會同時走向該食物的方向，表現出群體爭食或共享的可愛感。

## 4. 畫面與移動 (Visual & Movement)
- **自由走動機制**：不需要為寵物設定固定的站立位置，讓牠們沿用現有邏輯在房間內自由走動。
- **防碰撞處理 (Collision)**：
  - 引入輕量級的防重疊機制。
  - **碰撞邊界 (Hitbox) 微調**：防碰撞空間不要設定得太大。盡量讓兩隻寵物可以非常接近，表現得「好像快要黏在一起」，只要不出現完全重疊 (穿模) 即可。這樣能保留熱鬧與親密的感覺。

## 5. 命名與介面設計 (Naming & UI)
- **房間名脫鉤與智能繼承**：
  - 玩家加入第二隻寵物時，會觸發「房間重新命名」的步驟，為大家庭設立新名稱。
  - **智能繼承**：系統會自動將原本的「舊房間名稱」無縫轉移為「第一隻寵物」的專屬名字，讓玩家無需重複輸入而且合乎歷史邏輯。
  - 新加入的寵物則會在選擇後單獨進行一次命名。
- **名字標籤顯示 (Name Tags)**：
  - 預設在房間畫面中隱藏所有寵物的名字，保持畫面簡潔以及不妨礙家具佈置。
  - 採用「點擊閃現」：玩家實質點擊特定寵物時，才在該寵物頂部彈出名字標籤氣泡（維持 2~3 秒後淡出）。
- **代表寵物機制 (Main Pet Avatar)**：
  - **顯示邏輯**：在「房間選擇頁面」及「房間內左上角」，均統一只顯示當前設定為「代表寵物」的 GIF 頭像，保持 UI 簡潔。
  - **切換代表**：在房間內，玩家只需點擊左上角的寵物頭像，即可開啟切換選單，自定義哪隻寵物作為代表。此設定將即時同步生效於「房間選擇頁面」。
