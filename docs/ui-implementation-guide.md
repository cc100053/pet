# UI 素材交付與開發實作指南 (UI Implementation Guide)

本指南旨在解答「如何在不同尺寸螢幕上完美呈現圖片素材」，並提供給設計師的交付規格建議。

## 1. 核心概念：圖片如何變形？ (How Assets Scale)

在程式開發中，我們不會硬生生把圖片拉寬（那樣會變形）。我們主要使用以下兩種技術來應對不同尺寸：

### A. 向量圖 (SVG) - **首選推薦**
- **原理**: SVG 不是像素點，而是數學公式。
- **效果**: 無論放大縮小 100 倍，邊緣永遠清晰銳利。
- **適用**: 圖標 (Icons)、簡單的 Logo、功能性按鈕。
- **開發處理**: 我們可以在程式碼中任意指定它的長寬顏色，它會自動適應。

### B. 9-Slice Scaling (九宮格切圖法) - **PNG 按鈕必備**
如果必須使用帶有紋理或特殊邊框的 **PNG 位圖** 作為按鈕背景，我們使用「九宮格」技術。

**原理**:
程式會將圖片切成 9 塊：
1. **四個角落 (Corners)**: 保持原樣，**絕對不縮放** (保證圓角不變形)。
2. **上下左右邊緣 (Edges)**: 只單方向拉伸 (確保邊框線條清晰)。
3. **中間 (Center)**: 雙向拉伸以填滿內容。

**示意圖**:
```text
[1]--[2]--[3]
 |    |    |
[4]--[5]--[6]
 |    |    |
[7]--[8]--[9]
```
- 當按鈕變寬時：[2], [5], [8] 橫向拉長，[1], [3], [7], [9] 保持不動。
- **結果**: 無論按鈕裡面的文字有多長，按鈕看起來都像是原本設計的一樣，不會糊掉或變形。

## 2. 給設計師的交付規格 (Designer Checklist)

為了讓工程師能實現上述效果，請依照以下規格提供素材：

### 2.1 按鈕 (Buttons) / 對話框 (Dialogs)
- **格式**: PNG (透明底)。
- **切圖內容**: **只需提供底圖**。
  - ❌ **不要** 把文字 ("OK", "Cancel") 壓在圖片上。(文字由程式碼打上去，才能切換多國語言)。
  - ❌ **不要** 預留太多空白邊距 (Padding)。
- **如果不規則形狀**: 無法使用九宮格，請提供足夠大的高解析度圖片 (3x)。

### 2.2 圖標 (Icons)
- **格式**: **SVG (優先)**。
- 備案: 如果必須用 PNG，請提供 `@2x`, `@3x` 兩種尺寸。

### 2.3 全螢幕背景 (Backgrounds)
- **問題**: 手機螢幕長寬比差異大 (iPad 4:3 vs iPhone 19.5:9)。
- **解決方案**: 
  - **重要元素居中**: 讓主視覺集中在中間。
  - **邊緣可裁切**: 設計背景圖時，上下左右預留可被裁切(Bleed)的延伸圖案。
  - **分層給圖**: 例如「天空」一層、「草地」一層。程式碼可以根據螢幕高度，固定天空在頂部，固定草地在底部，中間自動填補，這樣就完美適配所有手機。

## 3. 開發實作範例 (Flutter)

(給開發者的備忘)

**處理 PNG 按鈕背景的 9-Slice:**
```dart
Container(
  decoration: BoxDecoration(
    image: DecorationImage(
      centerSlice: Rect.fromLTWH(20, 20, 10, 10), // 定義中間可拉伸區域 (x, y, w, h)
      image: AssetImage('assets/images/btn_bg.png'),
      fit: BoxFit.fill,
    ),
  ),
  child: Text("按鈕文字"),
)
```

**處理 SVG 圖標:**
```dart
SvgPicture.asset(
  'assets/icons/camera.svg',
  width: 24, // 程式控制大小
  height: 24,
)
```
