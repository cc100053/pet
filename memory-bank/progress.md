# Progress

## Recent Updates
- Added a project-local agent skill at `.codex/skills/release-notes-sync/SKILL.md` for future release-note work. It teaches agents to split one localized release-note input into two outputs: concise user-facing bundled What's New copy in `lib/shared/whats_new` / `lib/l10n/*.arb`, and verbatim per-locale App Store Connect `whatsNew` text in `.asc/version-localizations/*.strings` with an ASC CLI upload workflow.
- Polished the What's New modal into a compact content-driven layout: removed the icon hero's extra shadow treatment that created a dark band feeling, switched the version label into a small same-row pill beside the `Version update` title, capped the visible timeline to three items, and dropped the previous `Expanded`-driven body so the dialog now shrinks with its actual content instead of leaving a large blank lower area.
- Fixed the real What's New hierarchy bug: the modal had been reordered only inside `lib/shared/whats_new/whats_new_dialog.dart`'s body while still rendering through `AppDialog`, whose fixed header always painted the title before the body. What's New now uses its own dialog shell, so the actual shipped order is app icon hero -> version card -> `Version update` title -> subtitle -> timeline list -> CTA, and the gate test now asserts that the version card sits above the title.
- Added a Debug Tools preview action for the new What's New modal. The drawer can now force-show the current version's release-note dialog immediately through the same `ForceUpdateGate` render path used in production, and the debug preview bypasses persisted seen-state so the modal can be reopened repeatedly for style review without affecting the real one-time upgrade behavior.
- Added a one-time versioned "What's New" announcement flow for app upgrades. `ForceUpdateGate` now reads the installed public version, compares it with Hive-persisted `last_launched_app_version` / `last_shown_whats_new_version`, and shows the app-bundled release note exactly once only after a real upgrade. Fresh installs, same-version relaunches, downgrades, and versions without a local entry do not show a modal, while soft-update prompts still appear first and hard-update blocks still suppress the announcement. Added localized `1.0.5` release-note content plus policy/widget coverage for sequencing and repeat-prevention.
- Increased successful feed hunger recovery from 20 to 25 by updating the server-side `apply_pet_action` rule, so photo feeds now restore a quarter bar per valid feed while keeping the existing one-feed-per-10-minute burst limit and overfed behavior unchanged.
- Added quick photo-message actions to fullscreen viewer for Pet Home and chat image feeds: `FullScreenPhotoViewer` now shows bottom-corner `Reply` and `Emoji` actions for chat-linked photos, reply sends a normal text message with `reply_to_message_id`, emoji reuses the existing `message_reactions` flow, and unsynced local-only feed photos keep both actions disabled until a real `message_id` exists. Pet Home latest-feed snapshots now persist photo `message_id`s so expanded gallery photos can link back to chat, and added widget/unit coverage for viewer actions, feed-data message-id retention, and the shared action service.
- Upgraded store-purchase room cosmetic events to structured item-aware system messages plus push delivery: furniture/background purchase RPCs now store structured JSON with the bought item SKU/category, return the inserted `message_id`, chat localizes the exact purchased item name in all supported app languages, and `notify_friend` now validates/localizes `store_purchase` system messages so the other room members receive a Pet Home push for the purchase event.
- Expanded the Room Selection onboarding guidance without changing the normal layout: the onboarding overlay now highlights both the bottom create-room CTA and the existing top-right invite-code action at the same time, and the coach card copy explicitly tells users they can either create a room or join one by code. Added widget coverage for the dual-highlight Room Selection state plus shared focus-rect resolution and localization regression checks.
- Hardened the shared remote-image wrapper against deleted feed assets: `CachedNetworkImageView` now supplies `CachedNetworkImage.errorListener`, guards its aspect-ratio probe with `onError`, and adds `errorBuilder` to the inner render path so `404` R2 feed photos fall back cleanly instead of bubbling codec exceptions. Applied the same guard to the profile avatar framing editor’s direct image-stream path.
- Hardened fullscreen feed-photo loading against bad debug URLs: `FullScreenPhotoViewer` now gives `PhotoView` an explicit `errorBuilder`/broken-image fallback, so a simulated `404` feed image renders safely instead of bubbling an uncaught codec exception that can crash the app in debug.
- Tightened the Pet Home photo gallery caption layout so gallery and placeholder captions always stay on a single line with ellipsis overflow, sit slightly lower in the polaroid footer, and reserve bottom-safe caption space first so compact layouts no longer clip descenders at the card edge.
- Expanded the Pet Home photo gallery from 3 to 10 recent feed photos by introducing shared gallery feed helpers, updating room bootstrap/refresh/snapshot paths to keep 10 items for the active-room carousel while compact summary cards remain capped at 3.
- Fixed the transient self-feed ordering bug in Pet Home: optimistic local-path feed entries are now reconciled against canonical realtime/uploaded feed records instead of being prepended as a second photo, so a just-fed photo no longer briefly appears in slot 2 before refresh. Own-feed success now also snaps the gallery back to the newest photo at index 0.
- Rolled the chat-style keyboard collapse expectation out to every in-repo text-input surface. Added shared helper `lib/shared/ui/keyboard_dismiss_utils.dart`, wired `onTapOutside` unfocus into all 8 `TextField` usages (chat composer/report dialog, feed caption, profile nickname, pet naming, onboarding nickname, room join code, pet rename), and enabled drag-to-dismiss on the three scrollable input surfaces (`FeedCaptureView`, `PetSelectionPage`, onboarding profile setup overlay). Added widget coverage for the shared tap-outside and drag-dismiss helper behavior.
- Hardened the active chat route against two realistic crash/termination paths: async load/send/feed callbacks in `ChatRoomViewV2` now bail before mutating the chat controller after the route is disposed, and optimistic local feed images now decode with card-sized `cacheWidth` / `cacheHeight` plus a fallback placeholder instead of always decoding the original full-resolution file. This reduces disposed-controller races during fast navigation and lowers iOS memory pressure when large photos appear in chat immediately after send.
- Fixed the update-reminder blind spot on iOS: `ForceUpdateGate` still honors Supabase `app_config` for configured minimum/hard-update rules, but `AppConfigService` now treats those reads as best-effort and falls back to Apple lookup data for the latest App Store version/store URL when config is missing or stale. Added `AppStoreVersionLookupService` with storefront fallbacks plus regression tests covering config-missing and version-merge cases, so publishing a new App Store version can trigger the soft-update prompt without a separate backend config bump.
- Tightened the active chat reaction layout so emoji chips sit closer to the owning bubble/card with reduced vertical gap and tighter chip spacing, making it more obvious which message the reactions belong to.
- Removed the black shadow backdrop behind the active chat composer camera button in `ChatRoomViewV2`, leaving the camera pill as a clean circular surface without the extra dark square-ish base.
- Simplified V2 reply swipe: any non-system message, including self-sent messages, now supports swipe-to-reply, and the left-swipe trigger now fires on a shorter threshold as soon as the drag crosses it instead of waiting for gesture end.
- Removed the legacy chat-room implementation now that Home only opens `ChatRoomViewV2`: deleted the old `ChatRoomView`, `ChatMessageList`, and `ChatMessageTile` path plus its legacy widget tests, and removed the leftover `HomeView` V1/V2 route switch and unused legacy list key/imports so the codebase no longer suggests multiple active chat stacks.
- Restored the active chat route's package-level affordances after the deterministic-list refactor: `ChatRoomViewV2` now re-adds long-press action routing at the custom list layer and shows a floating jump-to-latest button again when the user scrolls away from the newest message.
- Added persisted emoji reactions and refined the active V2 chat interaction stack end-to-end: introduced room-scoped `message_reactions` with RLS, realtime publication, and a follow-up `user_id` FK index; extended cached/domain chat messages with grouped reaction summaries; and taught `ChatRoomViewV2` to best-effort load reactions, optimistically toggle one reaction per user, and refresh reaction state from realtime changes. Long-press now works on all non-system messages with quick reactions plus ownership-aware `Reply` / `Copy` / moderation actions, reaction chips render under bubbles/cards, reply previews are now integrated into the existing composer input pill and inside text/feed message surfaces instead of detached cards, dark-theme sent text/feed surfaces were lifted to a lighter muted teal, and the route now supports a left-half right-swipe back gesture that excludes the composer region. Added widget/unit coverage for action-sheet variants, reaction toggles, reaction chip taps, and half-screen back swipe behavior.
- Updated gameplay SFX to respect the phone silent-mode switch: `AppSfx` now plays eating and candy/coin reward sounds with `AudioContextConfig(respectSilence: true)`, so Home feeding/economy sounds stay muted when the device is silenced.
- Implemented room-aware notification tap routing end-to-end: `FCMService` now normalizes and dedupes notification tap intents from `onMessageOpenedApp`, `getInitialMessage`, iOS foreground local-notification taps, and a new Android `MainActivity` launch-intent bridge. `HomeView` now waits until bootstrap/room readiness, then routes `text` notifications into the target room chat while `image_feed`, `hunger_alert_*`, and other non-text room notifications land on the target room’s Pet home; stale or inaccessible rooms safely fall back to Room Selection. Added regression coverage for intent parsing, dedupe, and room-routing fallback decisions.
- Refined chat keyboard dismissal UX in both active and legacy chat routes: message timelines now use manual keyboard-dismiss behavior so users can scroll messages while the composer stays focused, and both chat routes now track downward drags across the screen so a swipe that starts in the message list and sweeps into the composer behaves like a Telegram-style drag. Touching the top of the composer only starts dismissal tracking; the swipe must continue farther down into the composer to dismiss, and dragging back up before crossing that threshold keeps the keyboard open. The direct composer-edge downward swipe path remains available too. The active/legacy chat bottom inset math now also clamps keyboard collapse against the safe-area inset, removing the previous downward dip / rebound at the end of keyboard dismissal. For the remaining Top Composer jitter, `ChatRoomViewV2` now only remeasures composer height when its content actually changes instead of on every build during keyboard animation, keeping the top edge and reply bar from twitching during collapse. Added widget regression coverage for list drag retention, tap-outside dismiss, composer-edge drag dismiss, list-to-composer sweep dismiss, partial-entry cancellation, the shared manual dismiss constant, and safe-area keyboard inset clamping.
- Replaced the active chat timeline’s package-managed lazy list with a deterministic eager-render list in `ChatRoomViewV2`: the screen now owns composer height, top-pagination anchoring, and a single `ScrollController`, while reply jumps load any missing older pages first and then animate exactly once to the target bubble/card center via `RenderAbstractViewport.getOffsetToReveal(..., 0.5)`. This removes the previous two-phase “materialize then correct” reply motion that came from mixing `flutter_chat_ui` list scrolling with app-side centering.
- Rebuilt reply-jump centering on a deterministic scroll path: `ChatRoomViewV2` now owns the chat list `ScrollController`, computes the exact center offset for the rendered target bubble/card via `RenderAbstractViewport.getOffsetToReveal(..., 0.5)`, and animates directly to that offset after any needed off-screen materialization step. This replaces the previous reliance on package alignment plus repeated `ensureVisible` corrections that could still visibly overshoot in the reversed list.
- Fixed the reply-jump centering regression introduced by the smooth-scroll refactor: for older targets that are not yet rendered, `ChatRoomViewV2` now keeps the smoother animated pre-scroll but restores a short post-render anchor centering correction, so replied-to messages land back in the middle of the viewport without reviving the old zero-duration overshoot.
- Refined reply-jump UX in active chat again: tapping a quoted reply no longer performs the previous zero-duration pre-jump followed by a second centering pass. `ChatRoomViewV2` now uses a single smooth scroll path per case, which removes the visible overshoot/rebound effect in the reversed list. The temporary reply-target highlight was also moved off the outer message envelope and onto the actual text bubble/feed card surface, so only the content frame gets the brief outline/glow.
- Fixed the real reply-jump centering root cause in active chat: reply taps now center on the target message via the rendered widget anchor (`Scrollable.ensureVisible`) instead of relying only on `flutter_chat_ui` / `scrollview_observer` alignment semantics, which still left targets too low in the reversed list.
- Centered reply jump targets in active chat: tapping a quoted reply now scrolls the source message to the middle of the viewport before applying the temporary highlight, instead of leaving it anchored too close to the bottom edge.
