# Progress

## Recent Updates
- Fixed the chat-room latest-scroll visibility gap that could hide the newest message slightly under the composer on initial entry or after tapping the `Latest` pill. The route now treats live-mode bottom positioning as sticky while late layout updates land: composer measurement changes plus async profile/reply/reaction hydration all re-run a short follow-up latest scroll when the user was already pinned near the bottom. Added widget regressions that simulate delayed reply-preview expansion after both room open and `Latest` pill navigation, then verify the newest message remains fully visible above the composer.
- Polished the Telegram-style chat density in three places. Reply previews are now flatter across the composer and message bubbles/cards, grouped message runs use tighter vertical spacing plus dynamic corner radii so stacks read more clearly, and the old jump-to-latest FAB is now a labeled `Latest` pill with the existing pending-count badge. Added widget coverage for the compact reply preview and the new grouped/jump affordances, then re-verified with `flutter analyze` and `flutter test`.
- Fixed the chat-room stale-latest gap after backgrounded notification arrivals. `ChatRoomViewV2` now observes app lifecycle resume events and runs a best-effort `_refreshLatest()` when the route returns to the foreground, so rooms that stayed open across a push-delivered message reconcile their latest window even if realtime did not visibly deliver the insert while backgrounded. Added widget coverage that simulates a background/resume gap with realtime disabled and verifies the newly arrived server message appears automatically after resume.
- Fixed the missing `1.0.5` What's New modal edge cases. The upgrade gate now tracks a persisted release signature (`version+build`) in addition to the public version, so `1.0.5+1 -> 1.0.5+2` can still surface the `1.0.5` modal if it was never shown before. `AppSettingsRepository.init()` also records whether the `app_settings` Hive box already existed, allowing the first tracked What's New rollout to treat pre-feature installs as upgrades instead of fresh installs. `WhatsNewService` no longer commits `last_launched_*` state before the dialog renders; it waits until the modal is dismissed (or policy decides nothing should show), preventing first-launch interruptions from permanently suppressing the announcement. Added regression coverage for same-version build upgrades, legacy installs, and deferred launch-state persistence.
- Updated received chat sender labels to feel more Telegram-like. `ChatRoomViewV2` now shows the sender name only on the first message in a consecutive grouped received run for both text bubbles and feed cards, instead of repeating the name on every bubble. Added widget coverage for grouped text+feed runs and timeout-broken groups, and kept a small history-pagination boundary exception so older-page prepends do not visibly jump the viewport by stripping the previous top message's label mid-scroll.
- Fixed the fresh Home Crashlytics lifecycle fatals found on iOS `1.0.4 (1)`. `HomeView._refreshPetState` and `HomeView._loadFurnitureInventory` now bail out immediately after awaited work if the widget was disposed, and they also guard their error-state updates the same way. This prevents room-entry/store refresh flows from calling `AppLocalizations.of(context)!` or `setState` on a dead `State`, which was the common cause behind Crashlytics issues `9861065cc5b9361c4c837c524cfa7380` and `e671d70a27168c4d25cfa75d9998b128`.
- Smoothed the chat upward-history loading UX. `ChatRoomViewV2` no longer inserts a spinner inside the timeline when loading older messages; it now shows a compact top overlay instead, captures the first visible message as a viewport anchor before prepending older pages, and reapplies scroll compensation across follow-up frames so the room stays visually steadier while history loads. Added widget coverage that verifies the overlay stays outside the scrollable timeline and that older-page loading keeps the visible viewport essentially anchored.
- Cleaned the retired coin-pack catalog residue from the live store backend. The inactive `iap_coin_pack_small` row had already been hidden from the app, but it still carried `iap_product_id = Petcoins120`; a new forward-only Supabase migration now strips the retired IAP metadata (`iap_product_id`, `iap_type`, `coin_amount`) so RevenueCat/App Store catalog checks no longer treat that unused product as part of the active integration surface.
- Fixed chat system-message alignment regression in the active route. `ChatRoomViewV2` now bypasses `ChatMessageEnvelope` for `system` rows, so `_SystemPill` keeps its intended centered layout instead of inheriting the left-aligned received-message wrapper. Added a widget regression test that asserts the rendered system message stays horizontally centered.
- Restored local-day separators in the active chat timeline. `DeterministicChatList` now inserts the same localized date pills the old chat list used (`Today`, `Yesterday`, `MMMd`, `yMMMd`), so `ChatRoomViewV2` once again groups messages visually by day without changing the existing bubble/card builders.
- Fixed unread-dot handling for self-triggered chat pet actions. Home unread logic now uses a shared helper so self-authored messages never increment unread when the chat is closed, and a forward-only Supabase migration updates new `clean_poop` system messages to store `sender_id = auth.uid()`. That keeps server-side unread/badge reconciliation aligned with the existing self-feed behavior while leaving historical clean-poop messages untouched.
- Reworked chat-room message loading around a bounded modern-history window to prevent large room histories from blowing up memory on entry. `ChatRoomViewV2` now hydrates only the latest 20 cached messages, refreshes only the latest 20 from Supabase on room open, auto-paginates 20 older messages when the user nears the top, and caps the in-memory visible slice at 80 by trimming the newest tail while browsing history. Realtime inserts now stay buffered while the user is in history mode, the floating jump button resets the room back to the latest window instead of only scrolling, chat cache persistence is limited to the newest 20 canonical messages per room, and new repository/helper/widget tests cover the bounded-window flows.
- Updated chat incoming-message presentation to match Telegram-style avatars more closely. Received non-system messages in `ChatRoomViewV2` now use a shared `ChatMessageEnvelope` wrapper that renders a circular profile icon slot on the left, reuses the existing `UserAvatar` renderer, and follows Telegram grouping behavior by showing the avatar only on the last bubble in a consecutive received-message group while preserving bubble-column alignment and existing reaction/reply UI. The avatar now also gets a small proportional upward visual offset, so it sits a bit higher without changing the grouping anchor rule.
- Added a shared light-surface status-bar default for standard app pages. `AppTheme.lightTheme` now sets `AppBarTheme.systemOverlayStyle` to `AppStatusBarStyles.light`, so non-Home/non-Chat screens with a regular `AppBar` consistently show dark iPhone time/battery content instead of depending on Flutter's per-screen default behavior.
- Hardened Crashlytics signal quality after the crash triage follow-up. The global light theme no longer uses `GoogleFonts.poppinsTextTheme()`, so app startup no longer depends on a runtime font fetch to `fonts.gstatic.com`. `CrashReportingService` now downgrades retryable transport/auth failures (for example `AuthRetryableFetchException`, socket/DNS timeouts, and similar network-layer errors) from fatal to non-fatal even when they bubble into the app-wide zone/platform error handlers, which prevents transient Supabase/auth/font fetch outages from polluting fatal crash counts or triggering the crash-update guard.
- Fixed the bright-theme iPhone status-bar contrast bug in the chat room. `ChatRoomViewV2` already resolved `AppStatusBarStyles.light/dark` from the room background theme, but the chat `AppBar` was not explicitly using that same overlay style. The route now applies the resolved `systemOverlayStyle` directly to the `AppBar`, so bright chat backgrounds restore dark time/battery content while dark themes keep light content.
- Added a diagnostics-first investigation path for the recurring iOS chat-room memory issue instead of changing cache policy again blindly. `MemoryDiagnosticsService` now records image-cache counts/bytes, active Supabase realtime channel count, and chat message/image/optimistic counts, keeps a rolling in-memory snapshot buffer for debug sessions, and emits lightweight Crashlytics breadcrumbs/custom keys for release builds. Home room switching, chat init/cache/network/load-more/dispose, and fullscreen viewer open events now all capture snapshots, while the Home debug drawer adds manual snapshot capture, image-cache clear plus snapshot, and a Memory Diagnostics bottom sheet for side-by-side repro review.
- Corrected the shared thumbnail downscaling change after it visibly stretched Pet Home gallery and chat-room image thumbnails: `CachedNetworkImageView` still applies cache bounds through the outer `CachedNetworkImage`, but the displayed image and aspect-ratio probe now use the original image provider again instead of an extra exact-size `ResizeImage` wrapper. This restores the prior thumbnail UI while keeping the non-visual cache protection.
- Updated the release-note drafting workflow in `.codex/skills/release-notes-sync/SKILL.md` to include a mandatory Phase 0 for localized draft approval. Updated `1.0.5` release notes across all ARB and App Store Connect `.strings` files with a focus on stability and security, and synced the new metadata to App Store Connect.
- Added a second layer of iOS image-memory protection after the chat-room `EXC_RESOURCE` findings: app startup now caps Flutter's global image cache to 150 entries / 192 MB in `lib/main.dart`. A first attempt to bound fullscreen viewer decode providers was reverted after it changed the shipped photo presentation, so fullscreen viewer UI remains on the prior implementation and the current protection focus stays on cache behavior plus the already-downscaled shared thumbnail paths.
- Fixed the reproducible iOS chat-room OOM on repeated room switching: device logs showed `EXC_RESOURCE (RESOURCE_TYPE_MEMORY)` stopping inside Flutter image upsampling, so the shared remote/local image path now derives decode/cache targets from the rendered viewport instead of letting thumbnails decode original-resolution assets. `CachedNetworkImageView` now sets `memCacheWidth` / `memCacheHeight` plus matching disk-cache bounds from layout constraints, and local file images loaded through the same wrapper now pass `cacheWidth` / `cacheHeight` into `Image.file`. Added a widget regression test that asserts the shared wrapper sizes its cache to the rendered bounds.
- Added a project-local Crashlytics triage skill at `.codex/skills/firebase-crashlytics-triage/SKILL.md`. It standardizes the fastest Firebase MCP workflow for this repo: confirm project/app ID, read the required Crashlytics guides, pull `topIssues` / `topVersions`, fetch sample events and stacks, and then map the failure path back into the codebase while checking whether the current repo already contains the likely fix.
- Migrated the repo-local Firebase Crashlytics MCP workflow to ADC/service-account auth so Codex no longer depends on expiring `firebase login` user credentials. Added `.firebase-mcp.env.example`, ignored the local `.firebase-mcp.env`, updated `scripts/start_firebase_mcp_crashlytics.sh` to load and validate `GOOGLE_APPLICATION_CREDENTIALS`, and refreshed `docs/firebase_crashlytics_mcp_workflow.md` with the service-account key path flow plus simplified `~/.codex/config.toml` wrapper setup.
- Added a repo-local Firebase Crashlytics MCP workflow for this workspace. `scripts/start_firebase_mcp_crashlytics.sh` now wraps `firebase mcp --dir /Users/fatboy/pet --only core,crashlytics`, and `docs/firebase_crashlytics_mcp_workflow.md` documents the required Firebase CLI reauth, Codex MCP server config snippet, verification command, and the recommended issue/event-driven fix loop for Crashlytics crashes and non-fatals against Firebase project `pet-app-702be`.
- Fixed the iOS Crashlytics dSYM auto-upload timing bug in the Xcode project: `ios/Runner.xcodeproj/project.pbxproj` had `Upload Crashlytics dSYMs` running before compile/embed work and before the custom `Generate objective_c dSYM` phase, so release/archive builds could attempt upload too early and miss required symbols. The upload phase now runs at the end of the Runner build phases after dSYM generation, preventing future versioned missing-dSYM warnings caused by repo configuration.
- Added `docs/whats_new_ai_implementation_guide.md`, an AI-facing reuse guide for this project's one-time versioned What's New system. It documents the detection/persistence/startup-flow architecture, the final compact modal style, the testing expectations, fallback architecture for projects without equivalent components, and the companion release-notes skill pattern for bundled copy plus ASC uploads.

It teaches agents to maintain bundled in-app What's New entries and App Store Connect release notes (`whatsNew` and SEO-optimized `promotionalText`) together. It uses a `.strings` file upload workflow with the ASC CLI to ensure correct multi-line formatting and manages localized copy across `lib/l10n/*.arb` and `.asc/version-localizations/*.strings`.
- Polished the What's New modal into a compact content-driven layout: removed the icon hero's extra shadow treatment that created a dark band feeling, switched the version label into a small same-row pill beside the `Version update` title, capped the visible timeline to three items, and dropped the previous `Expanded`-driven body so the dialog now shrinks with its actual content instead of leaving a large blank lower area.

What's New now uses its own dialog shell, so the actual shipped order is app icon hero -> version card -> `Version update` title -> subtitle -> timeline list -> CTA, and the gate test now asserts that the version card sits above the title.

The drawer can now force-show the current version's release-note dialog immediately through the same `ForceUpdateGate` render path used in production, and the debug preview bypasses persisted seen-state so the modal can be reopened repeatedly for style review without affecting the real one-time upgrade behavior.
