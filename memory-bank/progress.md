# Progress

## Recent Updates
- Refined the remaining chat keyboard movement regressions after fresh room feedback. `ChatRoomViewV2` now keeps the room background behind a separate static decoration layer while the whole interactive chat surface translates upward with the keyboard, so the composer no longer disappears under keyboard open and the currently viewed message is pushed upward at any history position instead of only in latest mode. Keyboard metric changes no longer restore a fixed history anchor that canceled that motion. The `Latest` pill also stays inside the composer's tap region, remains non-focusable, and is excluded from backdrop unfocus, so keyboard-open taps jump directly to newest messages without collapsing the keyboard first. Added widget coverage for history-mode upward push, composer upward movement, and keyboard-open `Latest` focus retention, then re-verified with `flutter test test/features/chat/chat_room_view_v2_bounded_window_test.dart`, `flutter analyze`, and `flutter test`.
- Refined the new Shop/Home decor follow-up UI after product feedback. Shop success floating cards now use the purchased item's own visual instead of a generic success checkmark, and the Pet Home room-decor hint is now a floating title-only chip above the inventory/decor action with a 5-second auto-dismiss plus a looping sweep highlight around the target button. Added widget coverage for the success-card visual payload and the floating hint/highlight dismiss behavior, then re-verified with `flutter gen-l10n`, `flutter analyze`, and `flutter test`.
- Refined the remaining Telegram-style chat regressions after device feedback. `ChatRoomViewV2` now preserves an actual reading anchor inside the currently viewed message, not just the bubble's top edge, so opening the keyboard or growing the composer while browsing history keeps the viewed content in place instead of only resizing the background. The `Latest` path now transitions through a merged live window before collapsing back to the newest 20-message slice, which removes the previous extent-shrink down-then-up scroll jitter during cache/network refresh plus delayed reply-preview expansion. Added a stronger widget regression that samples scroll offsets frame-by-frame and asserts `Latest` stays monotonic while the keyboard is open.
- Stabilized chat keyboard and latest-message positioning to feel more Telegram-like. `ChatRoomViewV2` now lets the route resize with the keyboard instead of faking keyboard movement through manual bottom insets, aligns the newest message against the actual visible area above the composer instead of blindly scrolling to `maxScrollExtent`, and uses a single viewport-sync path to coalesce entry/latest/layout follow-up adjustments. Keyboard open/close now preserves the visible anchor while browsing history and keeps live-mode rooms pinned above the input bar. Added widget regressions for keyboard-open room entry, keyboard-open `Latest`, and mid-history keyboard-open anchor preservation, then re-verified with `flutter analyze` and `flutter test`.
- Unified Shop purchase feedback around floating cards. Successful purchases no longer use bottom snackbars inside Shop; they now route through the same floating-card system as insufficient-funds feedback, and furniture/background success cards can present a `Return to room` CTA.
- Added a typed Shop route return contract so Home can distinguish ordinary room returns from a requested room-decor follow-up. After returning from a furniture/background purchase via the CTA, Pet Home now shows a transient guidance bubble beside the inventory/backpack control that tells the user how to enter room edit mode and start decorating. Added focused widget coverage for the floating notice card, route-result factories, Home guidance bubble dismissal, and the featured Pro banner's premium/status badges. Re-verified with `flutter gen-l10n`, `flutter analyze`, and `flutter test`.
- Moved the Shop-specific icons into `assets/shop/icon/*` and repointed all app image loads plus the bundled asset declaration to the new path. The old `assets/icon/shop/` directory is now gone, while the rest of the Shop feature rename and compatibility-sensitive `store_*` contracts remain unchanged. Re-verified with `flutter analyze` and `flutter test`.
- Renamed the in-app Store feature to Shop across the Flutter app. The feature folder, model/service/widget/test filenames, imports, `assets/shop/icon/*` references, and user-facing localization keys now all use `shop`/`Shop`, while compatibility-sensitive contracts such as Apple `App Store` copy, `store_url`, and structured `store_purchase` message payloads remain unchanged. Re-verified with `flutter gen-l10n`, `flutter analyze`, and `flutter test`.
- Hardened one intermittent chat send crash path in the active room route. `ChatRoomViewV2._handleSendMessage(...)` now blocks re-entrant sends before any pre-send async work starts and only restores the composer draft on failure while the route is still mounted, avoiding send-time races that could previously drive parallel send flows or mutate a disposed `TextEditingController`. Re-verified with the focused chat bounded-window suite plus `flutter analyze` and `flutter test`.
- Fixed the Memory photo Crashlytics fatal triggered when opening certain Memory images. `CachedNetworkImageView` now rejects non-finite explicit dimensions before deriving cache bounds, so callers like the Memory day sheet can keep using `width: double.infinity` for layout while the cache-size calculation falls back to the finite `LayoutBuilder` constraint instead of calling `.round()` on `Infinity`. Added a widget regression that covers the `double.infinity` width path and re-verified with `flutter analyze` and `flutter test`.
- Expanded adaptive title fitting to another home surface. The store's Pro banner and grid product-card titles already scale down to fit long localized names, and now the Home `Room Selection` header uses the same scale-down pattern instead of truncating with ellipsis. The store banner body still avoids inner scrolling, and the English Pro description remains shortened so the subscription card stays readable on compact screens.
- Upgraded the store purchase feedback to feel more game-like. Non-IAP `Buy` actions still stay tappable when the user lacks enough candy or diamonds, but the old bottom snackbar path is now replaced by a themed floating in-store notice card that uses the shop's existing candy/diamond visuals and shows current vs required balance. The normal store `Buy` buttons now also share the same press-in 3D interaction feel as the subscription CTA, while owned items, unavailable IAPs, and recovery-letter cards without a valid departed-pet target remain non-interactive. Focused store widget coverage remains in place for the grid-card routing and featured banner state.
- Restored the rebuilt Store featured-banner and theme-preview regressions without undoing the new single-buy card layout. The subscription banner now derives active state from RevenueCat entitlements again, shows localized premium/status/renewal copy per locale, disables the CTA for already-entitled users, and background item cards once again expose a preview affordance that opens the full room-theme dialog. Added focused widget coverage for the banner state/localization path and the restored theme preview dialog.
- Hardened the intermittent post-feed return path from the camera sheet back to Pet Home. `FeedCaptureView` now treats optimistic/upload callbacks as best-effort and reports thrown exceptions through `FlutterError` instead of letting them block `Navigator.pop()`, while Home's feed callbacks now bail out immediately when the Home state is already unmounted. Added a focused regression test for the callback wrapper so callback failures no longer strand the feed camera route.
- Fixed the chat-room latest-scroll visibility gap that could hide the newest message slightly under the composer on initial entry or after tapping the `Latest` pill. The route now treats live-mode bottom positioning as sticky while late layout updates land: composer measurement changes plus async profile/reply/reaction hydration all re-run a short follow-up latest scroll when the user was already pinned near the bottom. Added widget regressions that simulate delayed reply-preview expansion after both room open and `Latest` pill navigation, then verify the newest message remains fully visible above the composer.
- Polished the Telegram-style chat density in three places. Reply previews are now flatter across the composer and message bubbles/cards, grouped message runs use tighter vertical spacing plus dynamic corner radii so stacks read more clearly, and the old jump-to-latest FAB is now a labeled `Latest` pill with the existing pending-count badge. Added widget coverage for the compact reply preview and the new grouped/jump affordances, then re-verified with `flutter analyze` and `flutter test`.
- Fixed the chat-room stale-latest gap after backgrounded notification arrivals. `ChatRoomViewV2` now observes app lifecycle resume events and runs a best-effort `_refreshLatest()` when the route returns to the foreground, so rooms that stayed open across a push-delivered message reconcile their latest window even if realtime did not visibly deliver the insert while backgrounded. Added widget coverage that simulates a background/resume gap with realtime disabled and verifies the newly arrived server message appears automatically after resume.
- Fixed the missing `1.0.5` What's New modal edge cases. The upgrade gate now tracks a persisted release signature (`version+build`) in addition to the public version, so `1.0.5+1 -> 1.0.5+2` can still surface the `1.0.5` modal if it was never shown before. `AppSettingsRepository.init()` also records whether the `app_settings` Hive box already existed, allowing the first tracked What's New rollout to treat pre-feature installs as upgrades instead of fresh installs. `WhatsNewService` no longer commits `last_launched_*` state before the dialog renders; it waits until the modal is dismissed (or policy decides nothing should show), preventing first-launch interruptions from permanently suppressing the announcement. Added regression coverage for same-version build upgrades, legacy installs, and deferred launch-state persistence.
- Updated received chat sender labels to feel more Telegram-like. `ChatRoomViewV2` now shows the sender name only on the first message in a consecutive grouped received run for both text bubbles and feed cards, instead of repeating the name on every bubble. Added widget coverage for grouped text+feed runs and timeout-broken groups, and kept a small history-pagination boundary exception so older-page prepends do not visibly jump the viewport by stripping the previous top message's label mid-scroll.
- Fixed the fresh Home Crashlytics lifecycle fatals found on iOS `1.0.4 (1)`. `HomeView._refreshPetState` and `HomeView._loadFurnitureInventory` now bail out immediately after awaited work if the widget was disposed, and they also guard their error-state updates the same way. This prevents room-entry/store refresh flows from calling `AppLocalizations.of(context)!` or `setState` on a dead `State`, which was the common cause behind Crashlytics issues `9861065cc5b9361c4c837c524cfa7380` and `e671d70a27168c4d25cfa75d9998b128`.
- Smoothed the chat upward-history loading UX. `ChatRoomViewV2` no longer inserts a spinner inside the timeline when loading older messages; it now shows a compact top overlay instead, captures the first visible message as a viewport anchor before prepending older pages, and reapplies scroll compensation across follow-up frames so the room stays visually steadier while history loads. Added widget coverage that verifies the overlay stays outside the scrollable timeline and that older-page loading keeps the visible viewport essentially anchored.
- Cleaned the retired coin-pack catalog residue from the live store backend. The inactive `iap_coin_pack_small` row had already been hidden from the app, but it still carried `iap_product_id = Petcoins120`; a new forward-only Supabase migration now strips the retired IAP metadata (`iap_product_id`, `iap_type`, `coin_amount`) so RevenueCat/App Store catalog checks no longer treat that unused product as part of the active integration surface.
- Fixed chat system-message alignment regression in the active route. `ChatRoomViewV2` now bypasses `ChatMessageEnvelope` for `system` rows, so `_SystemPill` keeps its intended centered layout instead of inheriting the left-aligned received-message wrapper. Added a widget regression test that asserts the rendered system message stays horizontally centered.
- Restored local-day separators in the active chat timeline. `DeterministicChatList` now inserts the same localized date pills the old chat list used (`Today`, `Yesterday`, `MMMd`, `yMMMd`), so `ChatRoomViewV2` once again groups messages visually by day without changing the existing bubble/card builders.
- Fixed unread-dot handling for self-triggered chat pet actions. Home unread logic now uses a shared helper so self-authored messages never increment unread when the chat is closed, and a forward-only Supabase migration updates new `clean_poop` system messages to store `sender_id = auth.uid()`. That keeps server-side unread/badge reconciliation aligned with the existing self-feed behavior while leaving historical clean-poop messages untouched.
- Reworked chat-room message loading around a bounded modern-history window to prevent large room histories from blowing up memory on entry. `ChatRoomViewV2` now hydrates only the latest 20 cached messages, refreshes only the latest 20 from Supabase on room open, auto-paginates 20 older messages when the user nears the top, and caps the in-memory visible slice at 80 by trimming the newest tail while browsing history. Realtime inserts now stay buffered while the user is in history mode, the floating jump button resets the room back to the latest window instead of only scrolling, chat cache persistence is limited to the newest 20 canonical messages per room, and new repository/helper/widget tests cover the bounded-window flows.
- Updated chat incoming-message presentation to match Telegram-style avatars more closely. Received non-system messages in `ChatRoomViewV2` now use a shared `ChatMessageEnvelope` wrapper that renders a circular profile icon slot on the left, reuses the existing `UserAvatar` renderer, and follows Telegram grouping behavior by showing the avatar only on the last bubble in a consecutive received-message group while preserving bubble-column alignment and existing reaction/reply UI.
